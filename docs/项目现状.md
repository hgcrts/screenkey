## 五、本次自审修复总账（13 批真实缺陷 + 2 个新能力 + 2 项交互改造）

详细「以前 / 现在」对照见 [../README.md](../README.md#本轮自审修复记录)，机制与教训见
[架构.md](架构.md#八本轮全项目审计三类契约误解与一条半截管道)。

1. **B站以前 100% 连不上**（4 个缺陷叠加）：`_WsReadyHandler` 假设了 `blivedm` 不存在的钩子、
   且缺 `handle()` → 所有命令被 `AttributeError` 吞掉；`connect()` 里 `await self._join_task`
   违反基类「尽快返回」契约 → 线程永不退出；`stop_and_close()` 抛 `CancelledError`（不是 `Exception`）→
   清理代码整段跳过。
2. **抖音连接状态与心跳**：重连耗尽仍 `return True`、覆盖用户的停止请求、心跳绑在 `recv` 超时上
   （热门房间永不触发）、gzip 解压无上限、ack 发送失败先清队列、签名用的是一份从未更新过的陈旧参数、
   五项连接配置读了不用。
3. **筛选规则根本存不下来**：`FilterEngine.to_list/from_list` 与测试都在，
   但 `manager.save()` 的 payload 里没有 `filters` → 用户编辑的规则一重启就没。
4. **手改 `settings.json` 会让整个弹幕处理崩掉**：数值/布尔不转型
   （`"enabled": "false"` 变真、`"global_cooldown": "1.5"` 在比较处抛 `TypeError`）→
   现在逐字段强转、非法值回落默认。
5. **退出时会留下物理按下的键**：`_stopping` 全项目只写不读 → 现在真的拦按下、
   抬起永远放行，退出时释放所有键并 `join` 抓取线程。
6. **界面层线程安全**：热键监听线程直接调控件（会随机崩）→ 改成信号投递；
   统计读 `engine.stats` 改成加锁快照；模拟序列不再在 GUI 线程同步跑。
7. **编辑器会丢数据**：筛选编辑器浅拷贝规则（点「取消」也会写回引擎）+ 切行不回收当前编辑；
   映射编辑器 `.strip()` 把空格键触发词吃成空 → 无法映射空格。
8. **抖音 Cookie 粘贴 / B站扫码轮询**：DevTools 表格里的 TAB 被当分隔符（值丢失）、
   `Cookie:` 整行被丢弃；扫码轮询遇一次瞬时网络错误就终止、未知内层码被当 ERROR。
9. **模拟模式与平台工厂**：脚本发完后状态不复位（界面永远「已连接」）、
   辅助发送绕过 `_stopping`；平台名拼错会静默回落模拟器并「连上」。
10. **Node 签名桥与 protobuf**：子进程 stderr 管道写满会挂死、失败时不回收进程（孤儿 node）；
    `read_varint` 移位边界错误可产出 70 位整数、`get_int` 把字符串当整数解析。
11. **收尾**：`--selftest` 不再在项目根留下 `selftest\settings.json`；
    `force=True` 重配日志时关闭旧 handler；`hotkey.py` 补上 4 处 `undefined name 'Any'`；
    清掉约 48 处未用导入。
12. **按键「发出去了」却没人收到**：配置目录不可写 → 自动回落到可写位置；
    注入失败完全无声 → 新增警告通道（`kind="warning"`，不进错误统计）+ 启动自检。
13. **写状态时复核又抓到两个真缺陷**（都是这一轮自己引入或漏掉的）：
    ① `RotatingFileHandler` 打不开日志文件时会把整个程序打死 —— 退出码 1、**零输出、
       无窗口、无日志**；根因是"只看 `mkdir` 成不成功"（已存在的目录 `mkdir` 会成功，
       但往里写文件被拒）。现在改成**真写一个探测文件**，并按
       `DANMAKU_KB_LOG_DIR` → `~/.danmaku_kb/logs` → 程序旁 `.danmaku_kb/logs` → 临时目录
       依次回落；handler 构造失败只降级为"本次不记录文件日志"，绝不连累程序。
    ② 完整性探测**从来没成功过**：`ctypes.windll.kernel32` 没声明 `restype`，
       `GetCurrentProcess()` 的伪句柄 `(HANDLE)-1` 被截成 32 位 → `OpenProcessToken`
       在**任何**环境都失败 → "读不到令牌"被当成受限环境，**正常桌面用户也会收到假的
       「受限环境」警告**（作者本人的正常桌面运行就中了一次，日志为证）。
       现在显式声明原型，实测读到 `0x1000（中/普通用户）`；并且
       **读不到令牌不再当报警理由**（权威判据是回环实测），受限宿主改由
       `DSH_*` / Sandboxie 等宿主标记识别。
14. **【新能力】焦点窗口过滤**：`input/window.py`（493 行）+ 选项页分组 + 96 项测试；
    刻意 fail closed（正则写错 / 读不到前台 / 启用但目标为空 → 一律不注入）。
15. **【新能力】注入环境诊断**：`--check-env`、启动与切窗口自检、
    **回环实测**（注入 1px 鼠标移动再读光标）、受限宿主标记、`启动.bat` 预警。
16. **【交互改造】映射编辑器的按键列**：从"手打键名"改成**可搜索下拉**
    （`ui/key_selector.py` 的 `KeyComboBox` + `input/keycodes.py` 的
    `all_key_names` / `key_display` / `search_key_names` / `is_valid_key_name`，
    39 项离线测试）。四个坑：项文字用中文说明、真实键名放 `itemData`；
    可编辑下拉的 `currentIndex` 只对"用户真的选了某项"负责；
    校验口径从 `resolve_key`（任何单字符都能过，中文 `左` 也过）换成
    `is_valid_key_name()`，与控制器共用同一个函数；
    候选弹窗是 Qt 按字面匹配（`page down` 筛不出、`page` 能），
    所以**弹窗字面匹配、校验与存盘空白不敏感**，没有为了多词写法去自定义补全器。
17. **【交互改造】长按动作的按住时长**：映射编辑器「动作」列选**长按**时，
    以前按住多久只有 dataclass 默认的 `0.5` 秒，界面上根本改不了。
    现在键盘表与鼠标表都多了一列 **「长按(秒)」**（`0.05`–`5.00`，步进 `0.05`，两位小数，
    默认 `0.50`，载入时夹取越界值），值独立保存——动作不是长按时也照旧存着，
    「映射」总表的「动作」列对长按显示成 `长按 1.25s`（该列整体已改中文，见第 18 条）。
    这一列**按需出现**（用户反馈"常驻一列很突兀"）：表里没有任何一行选「长按」时整列收起，
    某行选了立刻出现、改回去又收起；行级也分两层——非长按的行看不到那一格，
    但值仍保留。实现是 `_refresh_hold_column()` 在「动作」下拉的 `currentIndexChanged`
    以及 `load()` / `add_row()` / `remove_selected()` / `duplicate_selected()` 后重算。
    实测链路：`ui/mapping_editor.py` 的 `_COL_HOLD` / `_coerce_hold()` →
    `long_press_duration` → `input/keyboard.py` 的 `execute()` 用
    `mapping.long_press_duration` 作为 `tap()` 的 `duration`。
18. **【显示修复】「动作」列以前是英文**：不进编辑器时，「映射」标签页总表的「动作」列
    直接显示枚举值（`press_and_release` / `click` / `scroll_up`），中文界面里很突兀（用户反馈）。
    现在总表走 `ui/mapping_editor.py::action_label()`，与编辑器下拉共用同一份中文文案
    （`按下并松开（点按）` / `长按 1.25s` / `单击` / `向上滚动`…）；没写中文说明的新枚举值
    回落显示 `value`，不会是空白。测试在 `tests/test_mapping_editor.py::TestActionLabel`
    与 `tests/test_ui_smoke.py::TestMappingTableRendering`。

## 六、已确证的环境性限制（**不是**代码缺陷）

1. **受限宿主静默丢弃注入**（本轮的用户故障）：`SendInput` 返回 1、`GetLastError() == 0`，
   但光标 / 按键状态毫无变化。**证据链是「回环实测」**：注入 1px 鼠标相对移动，
   再读 `GetCursorPos` —— 报告成功、坐标纹丝不动；鼠标这条判据没有
   `GetAsyncKeyState` 那种"桌面不活动就返回 0"的歧义，所以能一锤定音。
   旁证：`C:\Users\hgcrts` 的 ACL 其实给了本人完全控制（写不进去只能是进程被限制），
