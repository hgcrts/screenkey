## 1. 这是什么

**幕键（ScreenKey）把直播间的弹幕事件，变成你电脑上真实的键盘和鼠标操作。**

- 它连上直播间，监听**弹幕 / 礼物 / 进场 / 关注 / 点赞 / 上舰 / 醒目留言**等事件；
- 事件和你预先写好的**触发词**匹配上之后，它模拟一次**按键或鼠标动作**（按下、按一下、长按、连点、点击、滚轮、移动……）；
- 支持 **抖音** 和 **B 站** 两个平台；
- 全部在本机运行：弹幕从平台服务器直接拉到你的电脑，匹配和按键都在本机完成，**不经过任何第三方服务器**。

它**不是**什么：

| 它不是 | 说明 |
|---|---|
| 不是外挂 / 注入器 | 不读写游戏内存、不 hook 进程，只做系统级的合成键鼠输入 |
| 不代你登录 | 要你自己扫码（B 站）或粘贴 Cookie（抖音），账号始终是你自己的 |
| 不上传数据 | 没有服务端；弹幕内容、按键记录只在本机内存和本地日志里 |

> 合规提醒：直播间、游戏、平台对自动化操作各有规则。本项目是**个人自动化工具**，请自行确认你在用的场景允许模拟键鼠（例如单人游戏、自己的直播间互动、非竞技用途），并遵守平台用户协议。

## 2. 安装与启动

### 2.1 用打包版（推荐，不需要 Python）

1. 到 [Releases](https://github.com/hgcrts/screenkey/releases/latest) 下载 `ScreenKey-vX.Y.Z-win64.zip`；
2. **解压到一个纯英文路径**（例如 `D:\Tools\ScreenKey`），不要直接双击 zip 里的 exe 运行；
3. 双击 `ScreenKey.exe`。

目录里你应该能看到：

```
ScreenKey.exe            ← 主程序
_internal\               ← 运行库（别删、别单独移动 exe）
_internal\node\node.exe  ← 抖音签名用的运行时（v3.0.1 起内置）
README.md / README.en.md / LICENSE
```

> 升级时：先关掉程序，删掉旧目录，再解压新包。**不要**把新包覆盖到旧目录上混着用。

### 2.2 用源码（开发者）

```bat
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

装好依赖后，双击仓库根目录的 `启动.bat`（最省事），或者：

```bat
cd src
..\.venv\Scripts\python.exe -m screenkey
```

`启动.bat` 支持 `--console`（带控制台看报错）、`--selftest`（只自检）、`--check-env`（只查环境）。

### 2.3 首次启动会做什么

- 在 `%USERPROFILE%\.screenkey\` 建配置目录（老版本用户会被自动从 `~/.danmaku_kb` 复制一次）；
- 打开主窗口，四个页签：**连接 / 映射 / 选项 / 日志**；
- 不会自动连接任何直播间。

想先确认程序本身没问题，可以命令行跑自检：

```bat
ScreenKey.exe --selftest
```

它会把 Python 版本、Qt、配置、按键后端、签名引擎等逐项检查一遍并打印结果（退出码 0 = 全部通过）。

## 3. 三步连上直播间

### 第一步：选平台

「连接」页顶部 **平台** 下拉框：`抖音` / `B站`。

### 第二步：填房间号

在 **房间号 / 网址** 里填任意一种都行：

| 平台 | 可填 |
|---|---|
| B站 | `21414905`、`https://live.bilibili.com/21414905`、`https://live.bilibili.com/21414905?xxx=1` |
| 抖音 | `https://live.douyin.com/123456789`、`https://live.douyin.com/123456789?...` |

> 抖音必须用**直播间网址**（`/房间号` 那一段就是），不能只填一个数字 ID。

### 第三步：填凭证 → 开始接收

点 **获取凭证…**：

- **B站**：弹出一个二维码，用 B 站手机 App 扫码确认，成功后自动把 `SESSDATA` 填进来。二维码有有效期，过期点「刷新」。
- **抖音**：抖音的网页扫码接口早已不可用（要 JS 生成的 ttwid），所以这里是**分步引导**：
  1. 按对话框提示，在**浏览器里登录抖音**并打开直播间；
  2. 打开开发者工具（F12）→ Application / Storage → Cookies；
  3. 至少复制 `ttwid`（必需）；建议连 `sessionid`、`msToken`、`__ac_nonce` 一起复制；
  4. 粘进对话框（支持 `document.cookie` 格式、`name=value; name=value` 格式），点校验。校验只做格式/长度检查，不联网。

填好之后点 **开始接收**。看两个地方确认状态：

- 左侧 **状态**：`已连接` / `连接中…` / `已断开`，以及错误原因；
- 下方 **统计**：收到多少条、其中多少条触发了按键。

> 凭证会被加密保存（Windows DPAPI，字段前缀 `dpapi:`），只在你这台机器、你这个 Windows 账号下能解密。详见 [第 13 节](#13-配置文件日志与迁移)。

### 连不上时先看这里

| 现象 | 最可能的原因 |
|---|---|
| B站提示 `-352` | 凭证失效 / 过期 → 重新扫码；仍不行才是平台侧限制 |
| B站能连但没弹幕 | 房间号错了（填的是 short id 之类的旧号），或直播间没人说话 |
| 抖音提示签名失败 | v3.0 之前的旧包缺 node 运行时 → 换 v3.0.1+ 的包 |
| 抖音连不上、提示房间不存在 | 房间没开播，或网址格式不对 |
| 弹幕里昵称显示成 `伊***` 这种 | 你填的凭证已失效（程序会提示）；重新扫码即可 |

## 4. 主界面速览

顶部一排按钮：

| 按钮 | 作用 |
|---|---|
| **开始接收** | 按当前平台 / 房间 / 凭证连接，开始拉弹幕 |
| **停止接收** | 断开连接（配置不会丢） |
| **暂停按键输出** | 只暂停「模拟键鼠」，弹幕照常显示、照常记录；常用于临时接管键盘 |
| **显示弹幕窗** | 打开第 5 节的弹幕浮窗 |

四个页签：

| 页签 | 干什么 |
|---|---|
| **连接** | 平台、房间、凭证、模拟弹幕、当前配置文件位置 |
| **映射** | 弹幕触发词 → 按键 / 鼠标动作的对应表 |
| **选项** | 按键输出参数、弹幕显示参数、筛选规则、焦点窗口过滤、热键 |
| **日志** | 程序运行日志（不连接时也能看） |

## 5. 弹幕窗口

点 **显示弹幕窗** 打开，它是一个独立的悬浮窗，可以摆在游戏/直播画面的角落。

### 工具栏按钮

| 按钮 | 作用 |
|---|---|
| **暂停** | 暂停往窗口里追加（连接不中断），再点继续 |
| **清空** | 清掉当前显示的内容 |
| **导出** | 把当前列表导出成文本文件，方便回看/取证 |
| **只看触发按键的** | 过滤掉「不触发按键」的弹幕（进场、点赞这些） |
| **自动滚动** | 新弹幕来时自动滚到底部；翻看历史时可以关掉 |
| **置顶** | 让窗口悬浮在其它窗口之上 |
| **设置** | 打开「弹幕显示设置」 |

### 弹幕显示设置

| 设置项 | 说明 |
|---|---|
| 消息类型开关 | 弹幕 / 礼物 / 进场 / 点赞 / 关注 / 粉丝团 / 醒目留言 / 上舰，逐类开关，关掉后该类不再显示 |
| 时间戳 | 每行前面带 `HH:MM:SS` |
| 发送者昵称 | 显示昵称；关掉可以更省宽度 |
| 平台标记 | 抖音 / B 站 的彩色标签，双开时有用 |
| 自动滚动到最新 | 同工具栏 |
| 窗口置顶 | 同工具栏 |
| 字号 | 6–72 像素 |
| 最多保留行数 | 超过就丢弃最旧的（默认 1000 行，内存占用有上限） |

设置改完立即生效，并写回配置文件。

## 6. 按键映射

「映射」页展示当前生效的映射表，点 **编辑映射…** 打开编辑器。编辑器里两个页签：**键盘映射** 和 **鼠标映射**，各自是一张表，逐行可编辑。

### 6.1 表格的列

| 列 | 含义 |
|---|---|
| 启用 | 勾掉这一行就临时失效，不用删 |
| 触发词 | 弹幕内容里要出现什么；**多个触发词用英文逗号或中文逗号分隔**，例如 `w,w上,前` |
| 匹配方式 | 见下表 |
| 按键 / 鼠标键 | 目标键或鼠标键 |
| 动作 | 键盘：按下 / 松开 / 按一下 / 长按；鼠标：单击 / 双击 / 按下 / 松开 / 长按 / 移动 / 滚轮上 / 滚轮下 |
| 长按(秒) | 只有动作是「长按」时可调，0.05–5.0 秒 |
| 冷却(秒) | 同一条映射两次触发之间的最小间隔（默认 0.5），防止刷屏时按键风暴 |
| 说明 | 给自己看的备注，不影响行为 |

底部按钮：**新建 / 删除 / 复制 / 上移 / 下移**。顺序只影响界面展示；匹配时的优先级是：**精确相等 > 重复感应 > 包含/开头/正则**，同一档里**触发词更长的优先**（所以 `w上` 会先于 `w` 命中）。

### 6.2 匹配方式

| 方式 | 行为 | 例子 |
|---|---|---|
| 完全等于 | 弹幕内容 == 触发词（**对所有映射都会先校验一次**，所以「包含」模式的映射遇到内容完全相同也会命中） | 触发词 `1`，只有弹幕正好是 `1` 才触发，`11` 不触发 |
| 包含 | 弹幕里出现触发词 | 触发词 `冲`，`冲冲冲`、`我冲` 都触发 |
| 开头是 | 弹幕以触发词开头 | 触发词 `技能`，`技能一`、`技能二` 都触发 |
| 正则 | Python `re.search`（默认忽略大小写；多个触发词 = 多个候选正则） | `^[0-9]{3}$` 只匹配三位数字 |
| 重复感应 | 同一字符重复到次数阈值触发一次 | 触发词 `6`，弹幕 `666666` 会触发（阈值见下） |

「重复感应」的两个阈值在配置文件里可以调：达到 `short_press_count` 次视为一次短按，达到 `long_press_count` 次视为一次长按（配合动作「长按」使用）。

### 6.3 动作说明

| 动作 | 效果 | 典型用途 |
|---|---|---|
| 按下 | 键保持按下，直到你手动松开或程序退出时统一释放 | 持续移动 |
| 松开 | 松开某个键 | 结束「按下」 |
| 按一下 | 按下立刻松开（最常用） | 技能、跳跃、交互 |
| 长按 | 按住 `长按(秒)` 后松开 | 蓄力、长按交互 |
| 鼠标·单击 / 双击 | 左/右/中键点一下 | 点按钮、开枪 |
| 鼠标·按下 / 松开 | 保持按住 | 拖动、持续射击 |
| 鼠标·移动 | 相对当前光标移动 `dx, dy` 像素 | 视角微调 |
| 鼠标·滚轮上 / 下 | 滚 `scroll_amount` 格 | 切武器、翻页 |

> 点「停止接收」或关闭程序时，会统一释放所有仍处于「按下」状态的键，不会卡键。
> 「暂停按键输出」只是不再发送新的按键；如果暂停时有键还按着，建议先停止接收再接管键盘。

### 6.4 默认映射

首次运行带一套开箱可用的默认表：方向（`w/a/s/d` 与 `上/下/左/右`）、确认（`空格`/`回车`）、技能（数字键）、鼠标左/右/中键、滚轮。可以直接用，也可以点 **恢复默认映射** 一键还原。

### 6.5 试一下

映射页有「试一下：」输入框 + **测试匹配**：输入一段假弹幕，程序会告诉你它命中了哪条映射、会执行什么动作，**不会真的发按键**。调规则时先用它验证。

## 7. 筛选规则

「选项」页 → 筛选规则 → **编辑筛选规则…**。

规则是**有序列表**：从上往下逐条匹配，**第一条命中的规则决定这条弹幕的命运**，都没命中就走末尾的默认规则。

每条规则由三部分组成：

1. **条件**（可以多个，必须全部满足）：针对哪个字段（内容 / 昵称 / 用户 ID / 平台 / 消息类型）、比较方式（等于、包含、不包含、开头、结尾、正则、不在列表、长度大于/小于/等于）、比较值；
2. **动作**：
   - `allow` 放行（参与按键匹配）
   - `drop` 丢弃（界面也不显示）
   - `display_only` 只显示、不触发按键
   - `rewrite` 改写内容后再放行（可配合「剥掉指令前缀」把 `!技能1` 变成 `技能1`）
3. **范围**：可限定消息类型列表、可单独启用/停用。

默认自带两条：

| 规则 | 动作 | 作用 |
|---|---|---|
| 进入直播间不触发按键 | display_only | 进场 / 关注 / 点赞 / 统计只在界面显示，防止观众进出就乱按键 |
| 默认放行 | allow | 其余弹幕正常参与按键匹配 |

常见用法：

- 在**别人的直播间**里只想响应特定口令：加一条「内容 包含 `口令` → allow，其余 → drop」；
- 屏蔽机器人刷屏：条件「昵称 正则 `^用户\d+$` → drop」；
- 只在 B 站响应：条件「平台 等于 `bilibili`」再配动作。

## 8. 选项页：按键输出

| 设置 | 说明 |
|---|---|
| 启用按键输出 | 总开关。关掉 = 只显示弹幕、不模拟键鼠 |
| 游戏模式 | 用**扫描码**（`keybd_event` / SendInput 的扫描码方式）发送，兼容 DirectInput 游戏。普通窗口/浏览器建议关 |
| 单条弹幕最多触发 | 一条弹幕最多执行几个映射动作（默认 1，范围 0–10），防止一条弹幕触发一串操作 |
| 全局动作间隔（秒） | 两次按键之间的最小间隔，弹幕刷屏时限制频率 |
| 同一用户冷却（秒） | 同一用户在这段时间内的弹幕只处理第一条 |
| 相同内容去重窗口（秒） | 相同内容的弹幕在这段时间内只触发一次 |
| 暂停/恢复热键 | 全局热键，默认 `ctrl+shift+p`，见第 12 节 |

> 默认全为 0 表示不限速。**人多的大直播间建议开**：全局间隔 0.1–0.3 秒 + 同用户冷却 1–3 秒，体验会稳很多。

## 10. 焦点窗口过滤

只在你指定的窗口处于前台时，才真正注入按键。

| 项 | 说明 |
|---|---|
| 启用 | 勾上后，前台不是目标窗口就**一个键都不发**，弹幕照常显示 |
| 比对目标 | 窗口标题 / 进程名（按界面提示的写法） |
| 匹配方式 | 等于 / 包含 / 正则 |
| 目标内容 | 例如 `原神`、`chrome` |

典型用途：一边刷弹幕一边写代码，切到编辑器时不希望按键被注入。

## 11. 模拟弹幕（不连平台也能试）

「连接」页底部 **测试** 区：

1. 勾 **启用模拟弹幕**（不需要平台、不需要凭证）；
2. 设发送间隔（秒）；
3. 点 **发一条** 或 **发一组**，程序会把内置样例弹幕投进处理链。

用来验证「映射对不对、动作会不会执行、弹幕窗显示是否正常」，不用开播、不消耗任何平台接口。

---

## 12. 全局热键

- 默认 **`ctrl+shift+p`**：暂停 / 恢复按键输出，任何窗口下都生效（同一个开关和主界面的「暂停按键输出」按钮）；
- 在「选项 → 按键输出 → 暂停/恢复热键」里改，格式形如 `ctrl+shift+p`、`ctrl+alt+f9`；
- 热键注册失败（被其它软件占用）会在状态栏提示；此时换一个组合即可。

> 热键依赖 `pynput`。打包版已内置；源码运行时若提示不可用，`pip install pynput`。

## 13. 配置文件、日志与迁移

### 配置

| 项 | 位置 |
|---|---|
| 默认配置目录 | `%USERPROFILE%\.screenkey\`（可用环境变量 `SCREENKEY_CONFIG_DIR` 覆盖） |
| 主配置 | `.screenkey\settings.json` |
| 老版本（改名前） | `%USERPROFILE%\.danmaku_kb\`，首次启动会**自动复制**到新目录 |

- `settings.json` 里是 JSON：`connection`（平台/房间/凭证）、`display`（弹幕显示）、`input`（按键输出）、`window`（窗口位置）、`key_mappings`、`mouse_mappings`、`filter_rules`；
- 凭证字段保存为 `dpapi:` 开头的密文（Windows 数据保护 API，绑定当前用户），换机器/换 Windows 账号无法解密，程序会自动当成空；
- 手动改坏了也没关系：程序按字段做类型强转，坏字段回落默认值，不会因此起不来；
- 界面上「连接」页有 **打开目录** 按钮，一键定位配置文件所在目录。

### 日志

- 位置：`%USERPROFILE%\.screenkey\logs\`
- 按大小轮转，保留若干份；出问题时要日志，就把最新那份发出来。

### 便携模式

把 `.screenkey\` 目录放在 `ScreenKey.exe` 旁边，程序会优先用这个目录（适合放 U 盘/多环境）。

## 14. 常见问题

**Q：启动就退出 / 双击没反应。**
A：命令行跑 `ScreenKey.exe --selftest` 看输出；再不行删掉 `%USERPROFILE%\.screenkey\settings.json`（凭证会丢，其它配置重置）重试。杀软误报的话把安装目录加白名单。

**Q：B 站连上但不显示弹幕。**
A：确认房间**正在直播**且有人说话；确认房间号填对（右上角显示的房间号，不是短号）；看日志页有没有 `-352`。

**Q：B 站报 `-352`。**
A：先重新扫码——凭证过期是最常见原因。程序会区分「请求已签名仍被拒」和「签名缺失」两种提示；签名已内置，所以「已签名仍 -352」才是平台侧限制。

**Q：昵称显示成 `伊***`。**
A：你的 B 站凭证失效了，程序以游客身份在连（会给出提示）。重新扫码，`SESSDATA` 有效时昵称就是完整的。

**Q：抖音提示「签名引擎启动失败」。**
A：用的是 v3.0.1 之前的包。换新包；自检里可以看到 `node` 检查和 `sign.js` 检查两项。

**Q：按键没反应。**
A：依次检查：①「启用按键输出」是否勾上；②是否按了「暂停按键输出」；③「只看触发按键的」不影响触发，但筛选规则 `drop` 会；④目标窗口是否被焦点过滤挡住；⑤游戏内是否需要用「游戏模式」；⑥是否有杀软拦截合成按键（用「测试匹配」+ 日志区分是「没匹配上」还是「匹配上了但发不出去」）。

**Q：游戏里完全没反应，但记事本里有反应。**
A：开「游戏模式」（扫描码）；部分游戏需要以**管理员权限**运行本程序才能把按键送进游戏窗口。

**Q：能同时连两个直播间吗？**
A：当前版本一次只连一个房间。需要多个可以跑两份程序（各自不同的配置目录）。

**Q：会不会封号？**
A：程序不修改客户端、不注入进程、不代登录，只在本机模拟键鼠 + 读取公开弹幕。但平台/游戏对自动化的态度各自不同，竞技类场景请自行判断风险。

**Q：弹幕内容会外传吗？**
A：不会。没有服务端，只有「你 → 平台」的拉流连接，以及可选的本地日志。

## 15. 安全、隐私与合规

- **凭证**：只保存在本机 `settings.json`（DPAPI 加密），不发给任何第三方；程序只把你自己的凭证发给对应平台。
- **日志**：本地文件，可能包含弹幕原文（用于排障）；分享日志前自己看一眼。
- **输入模拟**：使用 Windows `SendInput` / `keybd_event` 合成键鼠事件，等同你本人在操作——不要在无人看管时对不可控的窗口开着全局映射。
- **合规**：遵守直播平台与游戏的服务条款；不要用于刷量、代练、多开挂机等违反平台规则的用途。

## 16. 卸载

1. 关闭程序窗口（Windows 任务栏右键关闭，或程序里停止接收后关窗）；
2. 删掉解压出来的 `ScreenKey` 目录；
3. 需要连配置一起清掉的话，删 `%USERPROFILE%\.screenkey\`（凭证、映射、日志都在这里）。

没有注册表项、没有系统服务、没有开机自启（除非你自己建了快捷方式）。
